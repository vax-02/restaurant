## 15. Bitácora de Decisiones Técnicas

Este apartado documenta las decisiones de arquitectura, herramientas y dependencias tomadas durante la fase de diseño y desarrollo del proyecto, justificando las elecciones tecnológicas frente a otras alternativas del mercado.

---

### 1. Framework Backend: Laravel vs. Node.js (Express/NestJS) vs. Python (Django)
* **Decisión:** Selección de **Laravel (PHP)** como framework principal del backend.
* **Justificación:**
  * **Ecosistema y Productividad:** Laravel provee soluciones integradas nativas para enrutamiento, ORM (Eloquent), colas, autenticación y manejo de comandos de consola (`Artisan`), lo que redujo drásticamente el tiempo de desarrollo del MVP.
  * **Manejo de Transacciones Complejas:** La gestión de estados de la compra (`pending`, `delivered`, etc.) y el control transaccional mediante `DB::transaction()` garantizan la integridad de los pedidos de forma robusta.
  * **Integración con Telegram:** Laravel facilita la abstracción de Webhooks/Polling y el procesamiento asíncrono de peticiones HTTP provenientes de la API de Telegram.
  * **Alternativas evaluadas:** *Node.js* ofrecía buen rendimiento de I/O pero requería armar la arquitectura desde cero (ORM, validaciones, migraciones), mientras que *Django* resultaba menos flexible para la manipulación directa de SDKs/APIs de mensajería rápida.

---

### 2. Base de Datos: MySQL vs. PostgreSQL vs. MongoDB
* **Decisión:** Uso de **MySQL** como Sistema de Gestión de Bases de Datos Relacional (RDBMS).
* **Justificación:**
  * **Estructura Relacional Definida:** El dominio del problema exige relaciones estrictas de integridad referencial entre entidades clave como compras detalles y demas
  * **Soporte de Tipos Espaciales/Coordenadas:** Permite almacenar las coordenadas de geolocalización (`latitude`, `longitude`) necesarias para el rastreo de delivery.
  * **Compatibilidad y Despliegue:** Compatibilidad nativa e inmediata con Eloquent ORM y facilidad de migración/respaldo en entornos de producción.
  * **Alternativas evaluadas:** *MongoDB* (NoSQL) se descartó debido a la falta de soporte nativo para transacciones complejas ACID necesarias en el flujo financiero y de inventario de un pedido.
